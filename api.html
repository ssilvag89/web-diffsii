Documentación de Integración B2B - DiffSii API

Esta API REST permite a sistemas externos (ERPs, CRMs o software a medida) inyectar movimientos comerciales (Compras y Ventas) directamente a la base de datos de DiffSii. El sistema aplicará deduplicación inteligente, validación de periodos y asentar los movimientos contablemente de manera automática.

1. Autenticación (Login)

Todos los endpoints están protegidos y requieren un token JWT. Para obtener el token, debes autenticarte en el endpoint general de DiffSii.

Request: Obtener Token

POST /api/auth/login-local

Body (JSON):

{
  "email": "usuario@tuempresa.cl",
  "password": "tu_password_segura"
}

Respuesta Exitosa (200 OK):

{
  "token": "eyJhbGciOiJIUzI1NiIsInR...",
  "user": {
    "id": 1,
    "name": "Juan Perez",
    "companies": [
      {
        "id": 10,
        "name": "Empresa de Prueba SpA"
      }
    ]
  }
}
Importante: Conserva el valor de token para usarlo en el header de autorización, y anota el id de la empresa (companyId) en la cual vas a inyectar los documentos.

2. Inyección de Movimientos Masivos

Este endpoint permite enviar un lote de facturas o boletas para un periodo contable específico.

Endpoint

POST /api/documents/company/{companyId}/upload-json

(Reemplaza {companyId} por el ID de la empresa obtenido en el Login)

Headers Requeridos

  • Authorization: Bearer {tu_token_aqui}
  • Content-Type: application/json

Estructura del Payload (JSON)

{
  "tipo": "ventas", 
  "periodo": "2024-04",
  "movimientos": [
    {
      "tipoDocumento": "33",
      "folio": 14502,
      "rutContraparte": "76123456-7",
      "montoNeto": 100000,
      "montoExento": 0,
      "montoIva": 19000,
      "montoTotal": 119000,
      "fechaEmision": "2024-04-15"
    }
  ]
}

Diccionario de Datos

  • tipo: Obligatorio. Solo acepta "compras" o "ventas".
  • periodo: Obligatorio. Formato YYYY-MM.
  • tipoDocumento: Código tributario del SII (ej: "33", "39") o nombre descriptivo.
  • folio: Número del documento (entero).
  • rutContraparte: RUT del cliente o proveedor (con guion y dígito verificador).
  • montoNeto, montoExento, montoIva, montoTotal: Valores numéricos enteros.
  • fechaEmision: Fecha en formato YYYY-MM-DD.

Respuestas y Códigos de Error - Servicio POST Movimientos

201 Created (Inyección Exitosa)

Ocurre cuando la petición fue procesada y se inyectaron los registros exitosamente.

{
  "message": "Registros insertados (Total: 1). Ignorados: 0.",
  "records": 1,
  "duplicates": 0
}
200 OK (Duplicados Detectados)

Ocurre si todos los registros que enviaste ya existen en la base de datos (mismo Folio, Tipo, RUT y Periodo). El sistema protege la integridad contable y los ignora automáticamente.

400 Bad Request

Error de formato en el JSON (ej. array vacío o tipo incorrecto).

403 Forbidden

Ocurre si el usuario del token no tiene permisos comerciales, o si intentas enviar más documentos del límite del plan.

409 Conflict

El periodo ha sido cerrado de forma contable por el administrador. No se aceptan inyecciones.

3. Descarga de Movimientos (Exportación)

Este endpoint permite a sistemas externos recuperar los movimientos (compras o ventas) previamente inyectados y procesados, incluyendo su estado de cuadratura actual.

Endpoint

GET /api/documents/company/{companyId}/movements

(Reemplaza {companyId} por el ID de la empresa obtenido en el Login)

Headers Requeridos

  • Authorization: Bearer {tu_token_aqui}

Parámetros de Consulta (Query Params)

  • periodo: (Opcional) Filtra los documentos de un mes específico (ej: "2024-05").
  • tipo: (Opcional) Selecciona el libro contable ("compras" o "ventas").
  • estado: (Opcional) Filtra por subestado del documento (ej: "Aceptado", "Pendiente", "Reclamado", "Excluido").

Respuestas y Códigos de Error - Servicio GET Movimientos

200 OK (Éxito)

Ocurre cuando la petición es procesada correctamente. Devuelve la lista de movimientos registrados en la base de datos de DiffSii según los filtros aplicados.

{
  "success": true,
  "count": 2,
  "data": [
    {
      "id": 105,
      "tipo": "ventas",
      "tipoDocumento": "33 - Factura electrónica",
      "folio": 14502,
      "rutContraparte": "76123456-7",
      "montoNeto": 100000,
      "montoIva": 19000,
      "montoTotal": 119000,
      "periodo": "2024-04"
    },
    "... otros documentos ..."
  ]
}
401 Unauthorized

Ocurre cuando no se envía el header Authorization con un token JWT válido, o si el token ha expirado.

{
  "error": "Token de autenticación inválido o no proporcionado."
}
403 Forbidden

Ocurre cuando el token es válido, pero el usuario no tiene los permisos suficientes asignados en la plataforma (RBAC) para el módulo solicitado (Compras o Ventas).

{
  "error": "Tu usuario no tiene acceso concedido para solicitar información del módulo de Ventas."
}
Nota: El mensaje variará indicando "Ventas" o "Compras" según corresponda al filtro enviado.
500 Internal Server Error

Ocurre si hay un problema de conexión con la base de datos o un error inesperado al procesar la solicitud en el servidor.

4. API Partner: Registro de Clientes

Permite a nuestros partners aprovisionar nuevos clientes (empresas) de forma programática. La empresa queda creada y habilitada, el usuario administrador recibe su enlace de bienvenida para activar su contraseña, y el RUT de la empresa queda inmediatamente autorizado en la llave partner para realizar consultas RCV.

Endpoint

POST /api/partners/clients

Headers Requeridos

  • X-Partner-Key: dsii_tu_llave_partner_aqui (o Authorization: Bearer dsii_...)
  • Content-Type: application/json

Parámetros del Request (JSON)

Todos los datos operativos y tributarios de la empresa son obligatorios para garantizar la emisión y sincronización automática.

  • rut: (Obligatorio) RUT chileno válido de la empresa (ej: "76.123.456-0").
  • razonSocial: (Obligatorio) Nombre legal o razón social (alias: name).
  • giro: (Obligatorio) Actividad o giro comercial de la empresa.
  • acteco: (Obligatorio) Código de actividad económica tributaria del SII (ej: "620100").
  • direccion: (Obligatorio) Domicilio comercial (alias: address).
  • comuna: (Obligatorio) Comuna tributaria.
  • ciudad: (Obligatorio) Ciudad tributaria (alias: city).
  • telefono: (Obligatorio) Teléfono de contacto comercial.
  • userEmail: (Obligatorio) Correo del administrador de la cuenta (recibe enlace para activar su contraseña).
  • siiPassword: (Obligatorio) Clave tributaria del SII para sincronizaciones periódicas automatizadas.
  • certificate: (Obligatorio) Certificado digital en formato PFX/P12 en base64 (alias: certificado, certificateBase64).
  • certificatePass: (Obligatorio) Contraseña del certificado digital (validada criptográficamente).
  • certificateName: (Opcional) Nombre original del archivo (ej: "certificado.pfx").
  • userName: (Opcional) Nombre del administrador (por defecto toma la razón social).
  • plan: (Opcional) "basico", "start" (por defecto), "prime" o "enterprise".
